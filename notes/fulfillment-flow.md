# 电商订单履约流程

用途：搞清楚一个订单从下单到售后要经过哪些环节、每一环节归谁负责、哪里会出问题，为延迟归因 agent 打基础。

## 一、7 个环节

下单 → 库存分配 → 拣货包装 → 发货 → 运输 → 签收 → 售后

## 二、每个环节：负责方 / 常见异常 / 后果

| # | 环节 | 负责方 | 常见异常 | 后果 | 会导致延迟送达？ |
|---|------|--------|----------|------|:---:|
| 1 | 下单（含支付、审核） | 客户、平台 | 付款没有及时到账（巴西的 boleto 要几天才能确认）；触发风控、待人工核实；地址填错；有特殊备注需要人工处理 | 订单晚进入处理流程，或被取消 | ✅ |
| 2 | 库存分配 | 平台、卖家 | 系统显示有货，实际已经卖完（超卖）；分仓失败 | 等待补货或取消订单 | ✅ |
| 3 | 拣货包装 | 卖家（仓库） | 拣错货或漏拣；库位上找不到货（账实不符）；包装破损；大促期间订单积压；特殊商品（如药品）需要审核；订单太大需要拆单 | 发货晚；错发漏发会转成售后问题 | ✅ |
| 4 | 发货（交给物流商） | 卖家、物流商 | 晚于发货截止日才交给物流商；面单错误或无法识别；物流商揽收不及时 | 包裹一开始就落后于计划 | ✅ |
| 5 | 运输 | 物流商 | 旺季积压；恶劣天气；中转延误；丢件或被盗；偏远地区线路本来就长 | 在途时间超出正常水平 | ✅ |
| 6 | 签收 | 物流商、客户 | 收件时无人签收（例如办公楼已关门）；地址错误；因包裹破损被拒收 | 二次派送或退回卖家 | ✅ |
| 7 | 售后 | 客户、卖家、平台 | 退货、换货、退款；差评 | 成本上升，评分下降 | ❌（这里不是延迟的原因，而是延迟后果显现的地方） |

## 三、哪些异常最终表现为「延迟送达」

第 1–6 步里的异常都可能导致延迟，按责任方归成三类：

- **卖家侧**（第 2–4 步）：缺货、备货慢、拣货包装出错、晚于截止日交给物流商
- **物流侧**（第 5–6 步）：在途积压、天气、中转、丢件、派送失败
- **客户 / 平台侧**（第 1、6 步）：付款慢、风控审核、地址错误、无人签收

第 7 步不是原因，延迟的后果会在这里显现出来：差评、退款。

## 四、和 Olist 数据的对应（项目要用）

| 环节 | Olist 字段 |
|------|-----------|
| 下单 | `orders.order_purchase_timestamp` |
| 审核通过 | `orders.order_approved_at` |
| 发货截止日（卖家的承诺） | `order_items.shipping_limit_date` |
| 交给物流商 | `orders.order_delivered_carrier_date` |
| 签收 | `orders.order_delivered_customer_date` |
| 承诺送达日（平台对客户的承诺） | `orders.order_estimated_delivery_date` |
| 售后评价 | `order_reviews.review_score`、`review_comment_message` |

**延迟归因思路（按时间戳把订单分段）：**

1. 是否延迟：签收时间 > 承诺送达日
2. 卖家段：交给物流商的时间 > 发货截止日 → 卖家交货慢
3. 物流段：签收时间 − 交给物流商的时间，和同一线路（卖家州 → 客户州）的平均在途天数比较，明显偏长 → 物流慢
4. 审核段：审核通过时间 − 下单时间，明显偏长 → 付款或审核慢

> 局限：Olist 没有拣货、分仓的时间戳，第 2、3 步的问题只能整体反映在「审核通过 → 交给物流商」这一段里。
